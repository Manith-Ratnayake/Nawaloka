# Ingestion

## Purpose

The ingestion stage prepares the generated website chunks for retrieval and stores them in OpenSearch.

Each chunk is cleaned, embedded, and indexed together with its source information.

## Process

1. Generated `chunks.txt` files are loaded from the chunking output.

2. HTML is converted into clean searchable text.

3. Each chunk is embedded using Qwen `text-embedding-v4`.

4. Embeddings use 1024 dimensions.

5. The OpenSearch index is created if it does not already exist.

6. The index stores the page name, chunk ID, clean content, original content, and embedding.

7. Embeddings are stored as KNN vectors using cosine similarity and HNSW.

8. Each chunk is indexed with a stable document ID.

## OpenSearch document

```text
page_name
chunk_id
content
raw_content
embedding_content_1024
```

## Environment variables

```env
OPENSEARCH_HOST=
DASHSCOPE_API_KEY=
DASHSCOPE_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
```

`OPENSEARCH_HOST` should contain the OpenSearch connection URL required by the configured OpenSearch service.

## Python dependencies

The ingestion script uses:

```text
beautifulsoup4
python-dotenv
openai
opensearch-py
```

## Run ingestion

From the repository root:

```bash
python ingestion/vector_database.py
```

The input should be the `chunking/chunk_output` directory generated by the previous stage.

## Output

After ingestion, the `nawaloka` OpenSearch index contains searchable text and vector embeddings used by the backend retrieval pipeline.
